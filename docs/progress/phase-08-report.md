## 3. Decisions and tradeoffs

- Tracing is optional and disabled by default. The first implementation uses no external collector;
  enabled processes write redacted, rotating local JSONL so the local release does not acquire a
  cloud dependency or transmit telemetry.
- Trace context is generated by the API and persisted in PostgreSQL. A worker never trusts a new
  browser-supplied context for resume/follow-up work.
- Span attributes are an allow-listed operational summary. Prompts, questions, raw model output,
  raw evidence, tool arguments, DSNs, and authorization values are excluded rather than relying
  only on a cleanup regex.
- Prometheus labels use bounded route templates, registered operation/tool names, task kinds, and
  outcomes. High-cardinality investigation and request IDs stay in traces/logs.
- Persisted event deletion is separate from normal startup and teardown. The normal command is a
  preview; deletion requires `retention --apply` and preserves investigations, evidence, reports,
  reviews, and checkpoints.
- No new ADR was necessary: these controls implement the accepted PostgreSQL durability and
  read-only scope decisions rather than changing architecture.

## 7. Limitations and risks

- Local JSONL is inspectable evidence, not a centralized trace backend. Multi-host export,
  encryption in transit, sampling policies, and collector availability are public-deployment work.
- Redaction plus data minimization passed named tests; this is not proof that every possible secret
  format can never appear. New attributes must remain allow-listed and receive regression tests.
- The in-process rate limiter, bearer-token identity, and loopback origin remain development
  controls, not enterprise multi-tenant security.
- The resource artifact is a single idle/light snapshot. It does not establish sustained capacity,
  peak memory, model latency, or production performance.
- Global unit-only coverage is 49.45%, below the retained 85 percent later-core target.
- Phase 2 captures still predate the Phase 3 corpus and must be recaptured before the final as-of
  evaluation pairing.

## 8. What I should understand

Trace propagation and durable recovery are separate. The W3C parent correlates observations, but
it does not schedule work or authorize it. PostgreSQL still owns the queued job, identity scope,
lease, generation, and fencing token. A trace ID is diagnostic metadata, never permission.

Interview question: **Why persist trace context instead of keeping it only in process memory?**

Answer: The API and worker are separate processes and the worker may start after a restart. A
server-stored parent lets later attempts remain correlated without treating the message queue or
checkpoint as an in-memory request continuation.

Interview question: **Why is prompt-injection defense enforced outside the prompt?**

Answer: Prompts are advisory. Typed schemas, a fixed tool registry, service authorization,
server-owned query templates, immutable cutoffs, and call/time/cost bounds reject unsafe model
output even when untrusted text asks the model to ignore instructions.
